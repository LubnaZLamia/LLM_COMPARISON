Reference

Help

How to use the app, and what every number means.

Using the app

  1. Task: ask the models for follow-up questions or a general reply.
  2. Patient Message: select an example message, or write your own.
  3. Select LLMs: tick the models to compare. They all get the same prompt. Optionally tick Score with judge model.
  4. Generate Outputs: the models are called in parallel. Each run gets its own link you can bookmark.
  5. Rate (optional): send the run to the Rate page for blind clinician scoring.

The highlight tiles show the leader in each metric. Table view shows the full analysis per model, and Download exports the run as CSV.

If a model fails. Rate limits (HTTP 429) and provider hiccups are retried automatically up to 3 times. If a model still fails, its card shows why and a Retry failed button re-runs only that model and merges the answer into the same run.

This is a research tool. Outputs are not medical advice and should be reviewed by a clinician.

Metrics (no ground truth needed)

Three headline metrics per task, shown as bars with the leader marked. Everything else is in Table view.

Follow-up questions

Questions Asked
How many questions the model asked. More isn't automatically better.
Topics Covered ↑
How many of 8 clinical areas the questions touch: onset & timing, severity, description, medications, other symptoms, red flags, medical history, impact & self-care. Found with keyword lists.
Agreement with Other Models ↑
Share of this model's questions that another model also asked, matched on shared meaningful words. High means it asked what everyone asked; low means it went its own way.

General response

Response Length
Word count.
Reading Grade Level ↓
Flesch-Kincaid US school grade. 8 or below is usually recommended for patient materials.
Key Elements ↑
Does the reply give emergency guidance, point the patient to their care team, and sound empathetic?

Compared with the clinician (example messages only)

Clinician Questions Matched ↑
For the questions task: the share of the clinician's own follow-up questions that the model also asked. One broad question ("any nausea or vomiting?") can cover two of the clinician's, and counts for both.
Clinician Reply Coverage ↑
For the response task: the share of the points in the clinician's own reply that the model's reply also covers.

This card is filled in for every example message. It is only skipped when you write your own message, since there is no clinician answer to compare against. Table view lists exactly what each model missed, and the closest match it did find, with the similarity.

How the match is made. A small model reads the clinician's questions and the model's answer and says which of the clinician's questions are covered, so a correct paraphrase still counts — "any blood in your stool?" and "have you noticed rectal bleeding?" match. It is asked only about coverage, never about quality, and never told which system wrote the answer. The card labelled Clinician Match (words) is the older word-overlap method, kept beside it as a baseline: where the two disagree, the difference is usually a paraphrase the word method missed. Set MATCH_METHOD in .env to meaning, lexical or both.

This is one extra call per output on the same key, tried once. If it fails, the card falls back to the word-overlap score rather than disappearing.

When a message has a chart summary, it is sent to every model (and to the judge) along with the message, so they work from the same information the clinician had. The results page shows it under the patient message.

Judge score (optional)

Tick Score with judge model and another LLM rates each output 1 to 5. Follow-up questions are rated on relevance, comprehensiveness, safety and clarity; replies on comprehensiveness, safety, empathy and clarity. The bar shows the average, and the table view shows each score plus the judge's reasoning. A judge can favour its own style, so it's best to pick a judge that isn't one of the models being compared.

In the table view

Per model: the topics it covered, questions only it asked, repeated questions, missing key elements, and the judge's scores and reasoning. Download exports all of it as CSV.

Word matching and keyword checks are quick and transparent, but they can miss paraphrases. The logic is in apps/comparisons/services/analysis.py.

Chat

The Chat page is a multi-turn conversation with one model. You play the patient.

  • Pick a model from the menu at the top. You can switch models mid-chat; each reply shows which model wrote it.
  • Replies stream in as the model writes them. Stop ends a reply early and keeps what was written.
  • Regenerate replaces the last reply, with the model currently picked. A failed reply shows Try again.
  • Memory: every message is saved. With each new message the model gets the most recent 20 messages (CHAT_HISTORY_MESSAGES in .env). Failed replies are left out.
  • Export downloads a chat as JSON, with model, timing and token counts for each reply.

Chats are stored on this computer and shared by everyone who uses this copy of the app.

Clinician rating

The Rate page collects human scores for outputs you have already generated.

  1. Type your name or initials once, then press Continue. It is stored with each rating so you can compare raters later — it is not a login.
  2. Pick a run from the list. Outputs appear as Model A, B, C in an order shuffled for you, so brand names can't sway the scores.
  3. Score each output 1–5 on fluency, coherence, relevance, factual correctness, completeness and safety, with an optional comment.
  4. Save, and the real model names are revealed alongside your scores.

Averages across raters appear as a Clinician Score card on the run's results page, and Download ratings CSV gives one row per rater per output for agreement analysis.

Rating the same run again updates your scores rather than adding duplicates. Every dimension needs a score before a run can be saved.

Setup

  1. Create a key at openrouter.ai/keys and add a few dollars of credit.
  2. Double-click run.bat. The first time, it asks for your key and saves it to .env.

To change the key later, edit OPENROUTER_API_KEY in .env and restart.

Each model carries a small shape badge in its own colour so you can follow it from the picker to the cards, the bars and the tables. The shapes are plain geometry, not company logos — the shape comes from the provider name and the colour from Colour in admin.

Each start, the app replaces model ids that OpenRouter has retired. To jump to the newest models on purpose, run python manage.py seed_models --refresh, or edit them in admin.

Where to change things

  • Prompts and judge criteria: apps/comparisons/services/prompts.py
  • Chat system prompt: apps/chat/services/prompts.py
  • Metrics and ground-truth matching: apps/comparisons/services/analysis.py
  • Dataset import: python manage.py import_datasets --questions data/questions.csv --responses data/responses.csv
  • Temperature, max tokens, judge model: .env
  • Models: Admin → LLM models
  • Past runs: Admin → Comparison runs
  • Past chats: Admin → Conversations
